# Proposals

One file per proposal: `IMP-nnn-slug.md`. The researcher writes them. The
orchestrator decides, and logs the decision in `docs/decision-log.md`. An adopted
proposal becomes a row in `docs/improvements.md`, marked "adopted, pending review";
a rejected one stays here with the reason, so it is not re-proposed from scratch.

A proposal is not a contract and not a decision. It argues a case; the code and a
verified run are what make it real.

Use `TEMPLATE.md`. Keep it short enough that the user can read it in a couple of
minutes — the depth belongs in the evidence, not in the prose.
