# Translations

- **Area:** internal
- **Online docs:** [Features](https://freeshow.app/docs/features)
- **Pinned code:** ff784eb
- **Confidence:** `code`

## Summary

The UI loads a JSON dictionary per language, falls back to English for any missing
string, and sends the same dictionary to remote clients. Right-to-left languages
set a direction store.

## Languages

- 31 files in `public/lang/`, including regional variants (`en_GB`, `en_ZM`,
  `pt_BR`, `pt_PT`, `zh_CN`, `zh_TW`, `cs_CZ`, `fr_FR`, `id_ID`).
- The published feature list names 20 languages. The file count is larger because
  of variants; the two lists are not the same kind of count. This is a `doc` vs
  `code` difference in presentation, not necessarily in coverage.

## Loading and fallback

`src/frontend/utils/language.ts`:

- The file is fetched by replacing `en` in the default path with the locale
  (`:40-44`).
- Missing top-level keys and missing nested strings are filled from `en`
  (`:49-60`).
- The dictionary is stored in the `dictionary` store (`:64`).
- The chosen locale is stored in `language` and sent to the main process
  (`:66-70`).
- Right-to-left locales set `localeDirection` to `rtl` (`:38`).

## Clients

Remote clients receive `{ lang, strings }` as a `LANGUAGE` message
(`src/frontend/utils/remoteTalk.ts:60`), so they do not load language files
themselves.

## Consequences for a port

- Falling back per key, including nested objects, is observable: a partially
  translated language shows English in the gaps, not blank labels.
- The remote contract carries the dictionary, so a client protocol that sends only
  a locale code would behave differently.

## Open questions
