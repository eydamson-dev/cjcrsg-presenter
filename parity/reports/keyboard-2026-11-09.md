# Keyboard and clear semantics — 2026-11-09

DEV-001: the controller had no keyboard shortcuts, so an operator working next
to a FreeShow install lost `Space` on every slide. It also uncovered that our
`clear` toggled while FreeShow's blanks — `Escape` twice would have unblurred the
screen, and navigation after a clear left it blurred.

## Bindings

Taken from FreeShow's controller (`src/server/controller/App.svelte`), not
invented:

| Key | Command |
| --- | --- |
| `Space`, `ArrowRight`, `PageDown` | next slide |
| `ArrowLeft`, `PageUp` | previous slide |
| `Escape` | clear (blank) |

Bound keys are captured (`preventDefault`) so `Space` and `PageDown` cannot
scroll the controller or press a focused button. Keys are ignored while the
focus is in an `input`, `textarea`, `select` or `[contenteditable]`.

## Where it lives

The page half is `apps/desktop/assets/keys.js`, included into the binary with
`include_str!`. It only captures keys and forwards their names through
`dioxus.send`. The mapping from key name to command is
`presenter_core::Command::from_key`, so there is exactly one binding table and
it is a Rust unit test.

The listener is on `document`, not an element: an operator must not have to
click the window first, and focus can sit on any button.

## Clear means blank

| Input | Before | Now |
| --- | --- | --- |
| `Escape` / Clear button / `/api/clear` | toggled blank | blanks, and a second press is a no-op |
| any navigation while blank | stayed blank | reveals the slide |
| `/api/restore` | did not exist | reveals the live slide without moving |

FreeShow derives "cleared" from whether an output has content, so any slide
change restores it. Ours now does the same: `ShowEngine::bump` resets the
cleared flag. Otherwise `Escape` followed by `Space` would leave the congregation
looking at black — the trap that made the old toggle indefensible.

## Measured

The live remote, with a restored 12-slide project:

```text
state   wed-1 cleared=False
clear   200
state   wed-1 cleared=True
clear   409  (409 = already blank)
restore 200
state   wed-1 cleared=False
next    200  (after clear, navigation restores)
state   wed-2 cleared=False
```

Artefact: `evidence/remote/clear-restore.txt`. The remote page now has Clear and
Restore buttons; `evidence/remote/remote-390x844.png` and `-1280x720.png` were
re-captured.

The key capture script was run in headless Chromium against the **same file the
app ships** (`parity/tools/check_keys.mjs`), with a stub `dioxus.send` recording
what it forwards:

| Case | Result |
| --- | --- |
| Space, ArrowRight, PageDown on the page | forwarded once, event prevented |
| ArrowLeft, PageUp on the page | forwarded once, event prevented |
| Escape on the page | forwarded once, event prevented |
| `a`, `ArrowUp`, `Enter`, `Home`, `End`, `Tab` | not forwarded, not prevented |
| Space, ArrowLeft, Escape while an `<input>` has focus | not forwarded, not prevented |

All 15 cases pass. Raw: `evidence/keys/keys-report.json`.

## Not verified

The one link the browser test cannot cover is **Dioxus delivering
`dioxus.send` from the real WebView to the Rust task**. It is the documented
eval bridge, the controller compiles and launches, but on this Wayland session I
cannot drive keystrokes into a window (no focus stealing, no reliable
window-targeted input). The manual check is:

1. `cargo run -p cjcrsg-presenter -- <file.cjcp>`
2. Press `Space` — the readout advances a slide.
3. Press `ArrowLeft` — it goes back.
4. Press `Escape` — the output blanks; press `Space` — the next slide appears.
5. Click into a text field, if one exists, and confirm `Space` types a space.

Until that is done, this report claims the bindings and the command semantics,
not the window wiring.

## Tests

- FreeShow's three key groups map to the right commands; unbound keys map to
  nothing; bound keys are captured;
- navigating after a clear restores the output and the position advances;
- clear blanks without moving, a second clear is a no-op, restore reveals
  without moving;
- first/last are reachable as commands;
- remote: clear blanks, second clear is 409, restore reveals, next after clear
  restores.
