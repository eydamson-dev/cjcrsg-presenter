# Exact-ish elastic and bounce easings — 2026-11-09

DEV-011: `elastic` and `bounce` were approximated by one cubic-bézier each,
which cannot represent either curve. They are now 101-point CSS `linear()` lists
sampled from Svelte's exact functions — the same functions FreeShow calls.

## How

`parity/tools/generate_easing.py` implements Svelte's `bounceInOut` and
`elasticInOut` from `svelte/easing` and emits a `linear(0, …)` string plus the
worst interpolation error over 1001 samples:

| Curve | Points | Worst error vs the exact function |
| --- | --- | --- |
| bounce | 101 | **0.0125** (1.25 %) |
| elastic | 101 | **0.0071** (0.71 %) |

The strings are embedded in `presenter_core::domain::easing_css`; a unit test
asserts they are `linear()` lists with 101 points, so a truncated paste fails the
build.

## Verified

- **Chromium** (`parity/tools/check_easing.mjs`): `CSS.supports` accepts both;
  a 1 s animation sampled at 25 % and 75 % matches the expected values to 0.000
  (bounce) and 0.011 (elastic, where opacity clamps to [0, 1]).
- **WebKitGTK**, the engine the app actually uses: the in-app probe reports
  `CSS.supports("animation-timing-function", "linear(0, 0.5, 1)") == true`.
- **Playwright WebKit** is not installed on this machine and its install failed
  host validation, so the curve sampling was not repeated in WebKit itself.

```json
{ "bounce":  { "supported": true, "at25": 0.141, "at75": 0.859, "error25": 0, "error75": 0 },
  "elastic": { "supported": true, "at25": 0,     "at75": 1,     "error25": 0.011, "error75": 0.011 } }
```

Raw: `evidence/easing/curves.json`, `easing-check.json`.

## Why not keyframes

One pair of keyframes per effect already exists; adding sampled keyframes would
mean a separate animation per easing per effect. A timing function keeps easing
orthogonal to the effect, which is the same model FreeShow uses.

## Residual

This is still an approximation: 1.25 % of the curve's travel, worst case, at 101
points. At a 400–1200 ms transition that is under 15 ms of positional difference
at the worst sample, below what an eye can follow. The report says the number
rather than claiming exactness.
