# Remote control and clear — 2026-11-09

Milestone: the walking skeleton's remote path, plus the first Phase 2 command
(clear/blank). No window is required to test any of it.

## What exists

| Piece | Where | State |
| --- | --- | --- |
| `SharedEngine` (Send + Sync engine handle) | `crates/core/src/shared.rs` | tested, incl. concurrency |
| HTTP remote | `crates/remote` | 6 tests, live smoke |
| `serve` subcommand | `apps/desktop/src/cli.rs` | headless, no display needed |
| Clear / blank | engine + remote + controller | tested |
| Remote started by the GUI | `apps/desktop/src/main.rs` | logs on bind failure, never blocks the UI |

Routes: `GET /`, `GET /api/state`, `POST /api/{next,previous,first,last,clear}`.
A command that changes nothing returns **409**, so a client can distinguish
"done" from "already at the end".

## Automated tests

```
cargo test -p presenter-core    24 passed
cargo test -p presenter-compat  12 passed
cargo test -p presenter-remote   6 passed
```

`SharedEngine` proves the engine is `Send + Sync`, that no-op commands do not
publish, and that eight threads advancing concurrently cannot skip or repeat a
slide (exactly two advances across three slides, final revision 2).

## Live smoke (headless)

```
GET  /api/state      → {"revision":0,"slide_id":"fx-1","position":1,"total":3,"cleared":false,…}
POST /api/next       → 200
POST /api/clear      → 200
GET  /api/state      → {"revision":2,"position":2,…,"slide":{…blank…}}
POST /api/first      → 200
POST /api/previous   → 409   (already at the first slide)
```

## Design notes

- **Clearing keeps the position.** A cleared output still reports `slide_id`, so
  a stage client can show "blanked at verse 3". This matches how an operator
  thinks about clear: it hides, it does not rewind.
- **One engine per process.** `OnceLock<Arc<SharedEngine>>`; two engines would
  mean two shows.
- **The server thread owns its runtime.** A bind failure logs and returns; it
  must never take the UI down.

## Not done

- The protocol is JSON-over-HTTP, not FreeShow's Socket.IO. Parity with existing
  FreeShow remote clients is a later milestone; this proves the command path.
- No authentication. It binds `0.0.0.0`, so it should be restricted before it
  runs on a shared network.
- Stage display content (next slide, clock, notes) is not modelled yet.
